- R-17 NetherNet: how Bedrock's NetherNet transport (replacing RakNet) affects Geyser, UDP tunnelling and the home-hosting relay (Q13/Q14). Report what Geyser supports today.
  - Result: **DONE 2026-11-20 — IMPORTANT.** NetherNet is Bedrock's new transport (replaces RakNet). Bedrock 26.60 was planned for **27 Oct 2026**, after which Bedrock clients no longer connect over RakNet — that date has PASSED, so Bedrock support now REQUIRES NetherNet. Geyser builds from #1237 support it (opt-in config). It needs signaling over TCP (HTTP) on the Geyser port PLUS UDP (WebRTC) for gameplay; `clone-remote-port` (sharing the Java port) no longer works with built-in signaling; fallback = external signaling (NXS), e.g. the free 'Warden' service, which needs only UDP. HAProxy headers are not yet supported for NetherNet gameplay. Built-in signaling is HTTP by default (players get a trust-on-first-use prompt); HTTPS via cert or reverse proxy. Likely explains the user's playit problems (tunnel must carry TCP + UDP). Sources: geysermc.org/blog/preparing-for-nethernet, geysermc.org/wiki/geyser/port-forwarding, /nethernet-https. **Impact:** docs/05, home-hosting helper (P7/P8), setup wizard must open TCP+UDP.

- R-19 Penalty limbo: cheapest way to hold a pack-declining player (configuration/limbo state, delayed keep-alives) without loading chunks.
  - Result: **PARTIAL 2026-11-21.** Configuration phase is before world/chunk play and is the likely low-cost holding point, but the protocol has no supported “slow keepalive” penalty mode; intentionally delaying keepalives risks the vanilla client's connection timeout. Prefer a bounded, no-chunk limbo in play phase with minimal entity/chunk traffic, or kick after a clear decline message. Benchmark connection memory and timeout behavior before implementing ADR-016's penalty option. Source: [Paper connection configuration API](https://jd.papermc.io/paper/26.3/io/papermc/paper/event/connection/ConfigureDisconnectEvent.html).
